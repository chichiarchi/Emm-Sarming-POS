Ah, you’ve run into PEP 668. Modern Linux distributions (like the latest Mint/Ubuntu) protect the system's Python from being "polluted" by pip. This is actually a good thing—it prevents you from accidentally breaking your OS.

To fix this for your POS project, you should use a Virtual Environment (venv). This creates a private "bubble" for your project where you can install whatever you want without affecting the rest of your computer.

The Fix: Step-by-Step
Run these commands in your terminal inside your project folder:

1. Install the environment creator (if you don't have it):

Bash
sudo apt update
sudo apt install python3-venv python3-full
2. Create your virtual environment:
(I'll call it venv, but you can name it anything).

Bash
python3 -m venv venv
3. "Activate" the environment:
This tells your terminal to use the Python inside your project folder instead of the system one.

Bash
source venv/bin/activate
Note: You will see (venv) appear at the start of your command prompt.

4. Now, install your libraries:

Bash
pip install PySide6 python-escpos
How to work with this going forward
Every time you open a new terminal to work on your POS, you must run source venv/bin/activate again.

When you are done, you can just type deactivate or close the terminal.

Inside VS Code/Cursor: If you use an editor, make sure to select the Python Interpreter located at ~/proj-test/Emma-Sarming-POS/venv/bin/python.

A Quick Tip for Hardware (Printers)
Since you are using python-escpos, you might run into a Permission Denied error later when trying to print to a USB device. To prevent this, add your user to the lp (printer) and dialout (serial) groups:

Bash
sudo usermod -a -G lp $USER
sudo usermod -a -G dialout $USER
(You'll need to log out and log back in for this to take effect.)
